# V8.5 — Раздельные кабинеты БГУ и модерация внутри ЦЦР

## Маршруты разработки
- `/admin` — панель ЦЦР; блок «Проверка новостей» ведёт к его внутреннему разделу `/admin/review`.
- `/admin/faculty` — самостоятельный кабинет факультета (11 вариантов для демонстрации).
- `/admin/department` — самостоятельный кабинет кафедры (17 вариантов для демонстрации).
- `/admin/review` — раздел ЦЦР, общий список новостей с одобрением/возвратом.

Каждый кабинет имеет собственную навигацию. В кабинетах подразделений есть обзор, демо-описание подразделения и редактор новостей. Факультет и кафедра не видят общую очередь ЦЦР и не имеют кнопки публикации.

## Важные ограничения
- Демонстрационный выбор факультета/кафедры **не является** аутентификацией; права не защищены на сервере.
- Данные хранятся в браузерном localStorage. Из V8.4 сохраняется ключ `bsu-editorial-workflow-demo-v2`; старые записи остаются.
- Редактирование описания сохраняется только в браузере, публичный сайт не обновляется.
- Для реальных сотрудников нужны серверные логины, проверка роли/подразделения в Backend и аудит решений; публичный API V7.4 не меняется.
- Административные страницы возвращают 404 вне development. Демоверсию нельзя открывать в продакшене.
- Не вводите реальные пароли, личные данные, конфиденциальные документы.

## Установка
1. Распакуйте ZIP в корень репозитория.
2. `node scripts/apply-ccr-review-link-v8.5.cjs` — внедряет ссылку из `/admin` и сохраняет backup `AdminWorkspace.tsx.v8-5.bak` (не коммить).
3. `npx tsc --noEmit`, `npm run lint`, `npm run build`, затем `npm run dev`.
4. Проверка: факультет → новость → отправить; `/admin` → «Проверка новостей» → одобрить/вернуть; факультет → увидеть статус.

Перед коммитом переместите .bak из `src` за пределы проекта. Backend/DB не изменяются.
