# BSU News 2.0 — контракт для backend (проект)

Две панели: `/admin/employee` и `/admin/ccr`. Роли `employee`, `ccr_moderator`, `ccr_admin`; проверка полномочий и принадлежности подразделению на сервере. Никакой третьей панели. Демо админки не следует включать в production до реальной авторизации.

## Публичная модель

`NewsRecord`: slug, title, excerpt, date (YYYY-MM-DD), category, sourceUrl, imageUrl?, content? (обычные текстовые абзацы), facultySlug?, departmentSlug?, tags?. `departmentSlug` требует согласованного `facultySlug`, проверяемого по БД. Отсутствие связей означает отсутствие подтверждённой привязки, а не выдуманное подразделение. Публичный массив `newsRecords` — только редакционный публичный снимок. Никогда не добавлять черновики, заявки, внутренние комментарии или приватные файлы в этот модуль: он импортируется клиентом и поиском.

GET `/api/v1/news?faculty=&department=&category=&year=&month=&search=&page=&limit=&locale=`: только опубликованные версии (publishedAt <= now), с пагинацией `{items,total,page,limit}`. GET `/api/v1/news/{slug}`: только опубликованная версия, иначе 404. Публичные DTO исключают служебные поля. При интеграции перевести главную, ленты подразделений, глобальный поисковый индекс и страницы статьи на тот же опубликованный источник; после публикации/снятия инвалидировать общие кэши, исключить снятую статью из поиска и CDN. Текущий frontend работает на локальном снимке, API пока не реализован.

## Модель заявки

`id`, `authorId`, `facultyId`, `departmentId?`, `status`, `revision`, `translations` (ru/ky/en/zh-CN: title, excerpt, body), `category`, `tags`, `mediaIds`, `createdAt`, `updatedAt`, `submittedAt`, `reviewerId?`, `reviewComment?`, `publishedAt?`. Сотрудник имеет доступ к своим заявкам; область подразделения определяется сервером из назначений. Изменения уже опубликованного материала — отдельная ревизия, старая одобренная версия остаётся публичной до одобрения новой.

Переходы: draft -> pending -> published | revision_requested | rejected. revision_requested -> draft -> pending. published -> withdrawn (только ЦЦР). Любое изменение после отправки требует новой редакционной проверки. Одобрение и запись опубликованной версии выполняются в одной транзакции; проверять ожидаемую ревизию, отклонять гонки с 409. Отложенная публикация только после одобрения; дата запуска проверяется сервером.

| Метод | Endpoint | Право |
| --- | --- | --- |
| POST | /api/v1/admin/news | сотрудник/ЦЦР |
| GET | /api/v1/admin/news | свои заявки / все ЦЦР |
| GET | /api/v1/admin/news/{id} | владелец / ЦЦР |
| PATCH | /api/v1/admin/news/{id} | автор в draft/revision_requested; ЦЦР по политике |
| POST | /api/v1/admin/news/{id}/submit | автор |
| POST | /api/v1/admin/news/{id}/approve | ЦЦР |
| POST | /api/v1/admin/news/{id}/revision | ЦЦР; комментарий обязателен |
| POST | /api/v1/admin/news/{id}/reject | ЦЦР; причина обязательна |
| POST | /api/v1/admin/news/{id}/withdraw | ЦЦР |

PATCH не принимает status, reviewerId, authorId или publishedAt от сотрудника. Запретить прямую установку статуса. 401 без сессии, 403/404 при чужом ресурсе. Журнал действий (actor, action, id, revision, timestamp), CSRF для cookie-сессий, MFA для ЦЦР, rate limits, защита от XSS. Rich text только с серверной санитаризацией; frontend текущей версии не использует dangerouslySetInnerHTML.

Медиа: закрытый карантин до проверки файла (сигнатура, размер, антивирус, удаление EXIF, безопасное перекодирование), приватный preview с авторизацией; публиковать только проверенные файлы под `/media/` или `/images/`. Никаких произвольных внешних URL в изображениях. В текущем фронтенде локальные raster-изображения; оптимизированные WebP/AVIF готовит медиа-процессор. Файлы хранить вне Git. При снятии публикации удалить доступ к закрытым медиа, если не используются другими публикациями.

Тесты backend: employee не может approve/publish/сменить подразделение; чужой черновик/медиа недоступен; pending/rejected не попадают в GET, поиск, главную или sitemap; параллельное одобрение не дублирует публикацию; повторная модерация правок; аудит и инвалидация кэша. Не считать текущую локальную версию полноценной защитой backend.
