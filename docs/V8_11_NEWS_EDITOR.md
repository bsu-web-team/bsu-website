# БГУ V8.11 — отдельный редактор новостей, обязательное одобрение ЦЦР

**Область применения:** только тестовое окружение. Не запускайте на основной базе `bsu`. Не объединяйте с `main` до согласования с бэкендером.

## Возможности
- Новая роль `news_editor`. Учётная запись без привязки к факультету/кафедре, создаётся вручную `python -m app.create_admin`.
- Отдельный интерфейс `/admin/editor`: редактор выбирает подразделение, пишет новости и отправляет на проверку.
- ЦЦР: `/admin/editorial-review` — просмотр отправленных заявок, возврат с обязательным комментарием, утверждение с публикацией.
- API `/api/v1/admin-editorial/items` и `/{id}/{submit|decision}`: роли проверяются исключительно FastAPI.
- Черновики в `editorial_items` PostgreSQL, публичная таблица `news` пополняется **только** после `approve:true` от ЦЦР.
- Публичный API V7.4 не меняется: его фильтр `is_published` остаётся действующим.
- Черновики других авторов не открываются редактором; обычный факультет и кафедра могут подавать новости только от своих подразделений, однако их старые демо-кабинеты всё ещё работают через localStorage и пока НЕ подключены к новому API.

## Установка
1. Сделайте Git-коммит/резервную копию, проверьте что установлен V8.10.
2. Распакуйте ZIP в корень проекта; запустите `python scripts/apply-v8-11.py`.
3. Проверьте `python -m compileall -q backend/app backend/alembic/versions`, `npx tsc --noEmit`, `npm run lint`.
4. Пересоберите образ **без перезапуска основного Backend**: `docker compose build api`.
5. Подключитесь к отдельной базе `bsu_auth_v88_test` через новый разовый контейнер и примените миграцию только в ней:

```powershell
$testUrl = "postgresql://bsu:bsu_local_password@db:5432/bsu_auth_v88_test"
docker compose run --rm --no-deps -e "DATABASE_URL=$testUrl" api alembic upgrade head
```

6. Создайте редактора только в тестовой базе:

```powershell
docker compose run --rm --no-deps -e "DATABASE_URL=$testUrl" api python -m app.create_admin
# Role: news_editor; password: unique 12+ chars. DO NOT share password.
```

7. Тестовый Backend на 8001 был создан ранее отдельным контейнером. Обновить его на новую версию **только после проверки**:

```powershell
docker stop bsu-auth-v88-api
docker rm bsu-auth-v88-api
docker compose run -d --name bsu-auth-v88-api -p 127.0.0.1:8001:8000 -e "DATABASE_URL=$testUrl" api
```

8. Сайт: `npm run dev -- -p 3100`. Вход `http://localhost:3100/admin/login`; редактор попадает в `/admin/editor`, ЦЦР — в `/admin`, модерация — `/admin/editorial-review`.

## Что ещё не готово
- Загрузка изображений и файлохранилище; поля фото намеренно не добавлены, чтобы не хранить небезопасные внешние URL.
- Защищённый CRUD факультетов/кафедр: старые формы являются демо, не полноценным серверным управлением.
- Журнал аудита, защита от перебора пароля, продакшен HTTPS, резервные копии и настройки безопасности.
- Обновление опубликованной новости после публикации, отложенная публикация, мультиязычная редактура.
- Публичная страница Next.js может потребовать пересборки/инвалидации кэша для отображения нового опубликованного материала; этот этап не гарантирует немедленное появление новости на фронтенде.
- Периодический запуск `app.seed` может удалить/перезаписать контент, включая опубликованное — не используйте seed после начала редакционной работы без отдельного миграционного плана.

## Безопасность
- Редактор НЕ может вызвать `decision`: `403`. Эндпоинты создания новости никогда не добавляют записи в публичную `news`.
- Нельзя использовать маршрут `/admin/review` (старый демо localStorage) как подтверждение реальной публикации: реальная очередь теперь `/admin/editorial-review`.
- Хранить пароли и токены в Git/скриншотах запрещено. Тесты вести на `bsu_auth_v88_test` и тестовом API `8001`.
