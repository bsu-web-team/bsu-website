# BSU V8.19 — структура подразделений и редакторы

**Сфера:** только тестовая БД `bsu_auth_v88_test` (API на `127.0.0.1:8001`). Публичная БД `bsu` и API `8000` не изменяются.

**Доступ:** `/admin/structure` для `faculty`, `department`, `ccr` в Next.js dev mode. 

**Заявки:** название существующего факультета/кафедры, создание факультета (только ЦЦР), создание кафедры от факультета или ЦЦР. Черновики и возврат на доработку. Изменения появляются в таблицах `faculties`/`departments` **только после** одобрения ЦЦР.

**Права:** ЦЦР может назначить существующему пользователю роль `ccr`, `faculty`, `department`, `news_editor`, прикрепить его к подразделению, активировать/отключить; все старые сеансы изменённого пользователя отзываются. Система не создаёт новых пользователей и паролей. Не разрешается править собственную запись или выключить последнего активного ЦЦР.

**Безопасность:** никаких удалений подразделений, без автоматической миграции связанных записей, контроль полномочий на Backend. Перенос уже существующей кафедры в другой факультет пока заблокирован, чтобы не нарушить связи сотрудников, программ, заявок и учётных записей. Привязка кафедры к факультету доступна при создании новой кафедры. Перенос будет отдельным этапом с проверкой зависимостей.

## Установка

Извлечь ZIP в корень `bsu-frontend`, запуск `python scripts/apply-v8-19.py`. Проверить `python -m compileall -q backend/app backend/alembic/versions`, `npx tsc --noEmit`, `npm run lint`. Затем:

```powershell
$testUrl="postgresql://bsu:bsu_local_password@db:5432/bsu_auth_v88_test"
docker compose build api
docker compose run --rm --no-deps -e "DATABASE_URL=$testUrl" api alembic upgrade head
docker rm -f bsu-auth-v88-api
docker compose run -d --name bsu-auth-v88-api -p 127.0.0.1:8001:8000 -e "DATABASE_URL=$testUrl" api
```

Перезапустить Next.js и открыть `http://localhost:3100/admin/structure`.

## Особенности

- Существующие slug не изменяются при переименовании, чтобы не сломать ссылки.
- Новым подразделениям присваиваются уникальные служебные slug до отдельной проверки человекочитаемых адресов.
- Факультет и кафедра без локального заполнения остальных полей будут отображаться с пустыми описаниями до редактирования профиля.
- Для новых аккаунтов используйте существующую отдельную CLI-процедуру создания пользователей, а не новую панель.
- Не объединять ветку в `main` до полного интеграционного тестирования.
